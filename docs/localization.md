# Navigation localization

Pass the app language through the existing `locale` prop:

```tsx
<MapboxNavigationView coordinates={coordinates} locale="es-MX" />
<MapboxNavigationView coordinates={coordinates} locale="en-US" />
```

The library's own UI supports Spanish and English, including their regional
variants and underscore-separated identifiers such as `en_US`. Missing, empty
or `default` locales use the device locale. Custom UI strings fall back to Spanish
for other languages; Mapbox retains its own supported-language behavior.

The prop controls:

- Mapbox route/matching language, visual maneuver instructions and voice.
- Map labels and Mapbox native UI resources.
- Continuation instructions, off-route/loading/unavailable states and errors
  generated by the library.
- Missing/error speed-limit labels and accessibility descriptions.
- Overview/follow and mute/unmute/cancel accessibility labels.
- Default marker letters (`P` in Spanish, `S` in English).
- Number/date formatters and the unsupported-web message.

Road/place names, marker titles, explicit marker letters and `bottomLegend` are
content supplied by the map provider or consumer and are preserved. Existing
geographic speed-unit selection is also preserved. Technical errors returned by
external providers remain diagnostic payloads rather than library UI strings.

Changing `locale` refreshes owned labels and the current speed-limit state
immediately. Cached planned-route guides are invalidated and re-requested in the
new language; old-language route revisions cannot enable guidance. iOS recreates
SDK UI for the new locale while preserving camera state, custom markers and the
consumer's bottom legend. Its resource-bundle override is limited to Mapbox
bundles and never writes the host app's `AppleLanguages` preference.

## Translation source

Edit `src/configs/localization/navigationStrings.json`, then run:

```sh
npm run generate:localization
npm run check:localization
```

The generator writes typed Kotlin and Swift catalogs. JavaScript imports the same
JSON directly. Commit the generated native files together with the JSON changes.
`npm run build` and the installation's `prepare` lifecycle also generate catalogs
and copy the JSON into the build output. The project's `tsconfig.json` enables
`resolveJsonModule` and is maintained manually so Expo's configuration step
preserves this setting during installation.
Generation avoids rewriting unchanged files so concurrent native compilation can
read them safely when the catalog has not changed.

See `tests/README.md` for shared locale fixtures, live prop-change regression tests
and native bundle-isolation checks. Device verification should switch Spanish ↔
English while following a planned route, in overview, without speed-limit data,
and with voice both muted and enabled. Native changes require a new app build.

Mapbox's [localization guide](https://docs.mapbox.com/android/navigation/guides/localization/)
documents how its route/voice language and native formatters are configured.
